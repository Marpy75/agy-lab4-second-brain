# Second Brain — Локальна система навчальних нотаток (PARA)

Персональна локальна система управління знаннями (Second Brain) для студента, оптимізована для структурування конспектів за методологією **PARA** (Projects, Areas, Resources, Archives + Inbox). Забезпечує зберігання даних у відкритому форматі Markdown (`.md`) із метаданими YAML Frontmatter, перехід за двосторонніми зв'язками `[[Назва нотатки]]`, підсвітку коду та миттєвий пошук без сторонніх бібліотек чи баз даних.

---

## 📋 Вимоги до середовища

- **Node.js**: версія **18.0.0+** (рекомендовано актуальну LTS версію).
- **Сторонні залежності**: **відсутні** (проєкт принципово використовує лише стандартну бібліотеку Node.js: `http`, `fs`, `path`, `url`, `node:test`, `node:assert`).
- **Веб-браузер**: будь-який сучасний браузер (Chrome, Firefox, Edge, Safari).

---

## 🚀 Інструкція запуску

### 1. Запуск сервера застосунку
У терміналі виконайте:
```powershell
npm start
```
Сервер запуститься в ізольованому локальному режимі. Відкрийте у браузері:
👉 **[http://127.0.0.1:3000](http://127.0.0.1:3000)**

### 2. Запуск автоматизованих тестів
Для перевірки валідації безпеки (Path Traversal), парсингу Frontmatter, пошуку кирилицею, фільтрації за тегами та м'якого видалення виконайте:
```powershell
npm test
```
Тести виконуються нативним тест-ранером Node.js (`node --test tests/`).

## 🏛 Архітектура системи

Система побудована за принципом **Local-First / Zero-Dependencies**:
- **Серверний рівень**: нативний модуль `http` обробляє REST API та роздає статичні файли фронтенду.
- **Рівень збереження**: відсутність зовнішніх СУБД; усі нотатки — це відкриті `.md` файли на диску.
- **Захист від Path Traversal**: суворий білий список категорій PARA, заборона послідовностей `..`, `/`, `\`, обов'язкова наявність розширення `.md`.
- **Безпечне видалення (Soft Delete)**: операція `DELETE` не знищує файл фізично, а переносить його в `notes/Archives/` та оновлює статус на `archived` після обов'язкового підтвердження користувачем.
- **Власний захист від XSS**: безпечне відображення без стороннього `DOMPurify` завдяки власному екрануванню спецсимволів (`<`, `>`, `&`, `"`, `'`).

> [!NOTE]
> Детальний архітектурний опис, потоки даних, діаграми Mermaid, модель нотатки та матрицю ризиків наведено у документі [docs/architecture.md](docs/architecture.md).

## ⚠️ Обмеження системи

1. **Типи підтримуваного контенту**: система орієнтована на чистий текст Markdown та блоки коду з підсвіткою синтаксису. Формули LaTeX/KaTeX, важкі PDF-документи та вбудовані медіафайли **не підтримуються**.
2. **Формат файлів**: допускаються виключно файли з розширенням `.md` та обов'язковим блоком YAML Frontmatter на початку.
3. **Механізм пошуку**: реалізовано лінійний перебір файлів у пам'яті (без побудови окремого важкого індексу FTS). Оптимально для колекцій обсягом до кількох сотень або тисяч нотаток.
4. **Фізичне видалення**: у системі навмисно вимкнено повне видалення файлів з диску через UI, щоб запобігти випадковій втраті конспектів.
5. **Контур штучного інтелекту**: застосунок не містить вбудованих LLM та не здійснює мережевих запитів до хмарних AI-провайдерів. Сортування, тегування конспектів з `Inbox` та аналіз зв'язків виконує зовнішній **Agent Skill** в Antigravity локально над файлами.

## 🔒 Політика приватності та безпеки

- **Тільки навчальні дані**: система спроєктована виключно для ведення конспектів, лабораторних робіт та навчальних нотаток. **Категорично заборонено** зберігати паролі, приватні токени доступу, API-ключі чи персональні конфіденційні дані.
- **Сувора мережева ізоляція (127.0.0.1)**: HTTP-сервер слухає виключно інтерфейс `127.0.0.1`. Він недоступний для інших пристроїв у спільній локальній мережі (Wi-Fi гуртожитку або комп'ютерного класу ВНЗ).
- **Повна відсутність телеметрії**: жоден фрагмент ваших конспектів, пошукових запитів чи логів не надсилається на зовнішні сервери.
- **Захист від XSS**: користувацький вміст обробляється власним алгоритмом санітизації (Zero-DOMPurify) перед формуванням DOM-дерева.

## 💾 Як робити резервну копію (Backup Guide)

Для надійного збереження даних рекомендується регулярно створювати резервні копії одним із двох методів:

### Варіант А: Локальне або віддалене збереження через Git (Рекомендовано)
Оскільки всі конспекти — це звичайні текстові файли, система ідеально версіонується:
```powershell
# 1. Перевірити стан змінених конспектів
git status

# 2. Додати створені конспекти до індексу
git add notes/

# 3. Зафіксувати зміни комітом із датою
git commit -m "Оновлення навчальних конспектів за $(Get-Date -Format 'yyyy-MM-dd')"

# 4. (Опційно) Надіслати у власний приватний репозиторій
git push origin second-brain-ver2
```

### Варіант Б: Створення офлайн ZIP-архіву
У терміналі PowerShell у папці проєкту виконайте команду для створення архівованого знімка папки `notes/`:
```powershell
Compress-Archive -Path notes -DestinationPath ("backup-notes-" + (Get-Date -Format "yyyy-MM-dd") + ".zip") -Force
```
Отриманий `.zip` архів можна зберегти на зовнішній флеш-накопичувач або зберегти на хмарний диск вручну.
